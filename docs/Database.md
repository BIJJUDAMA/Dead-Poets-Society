## Schema Overview

The database uses PostgreSQL managed by Supabase. User authentication is handled through `auth.users`, with profile metadata mirrored into `public.profiles`. The database implements strict Row Level Security (RLS) across all tables to protect user data and ensure authorized access.

```
auth.users (Supabase Auth)
    │
    ▼ (1:1 via trigger)
public.profiles
    │
    ├──< public.notes (Poet's published poems)
    │        │
    │        ├──< public.applauses (Many-to-many applause tracking)
    │        │
    │        └──< public.bookmarks (Many-to-many user bookmarks)
    │
    └──< public.poem_submissions (Review queue for approval)
```

## Tables and Columns

### 1. public.profiles

Stores user profile information, roles, and social graph links.

| Column | Data Type | Constraints | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `UUID` | `PRIMARY KEY`, `REFERENCES auth.users(id) ON DELETE CASCADE` | None | Unique user ID matching auth.users |
| `updated_at` | `TIMESTAMPTZ` | Nullable | None | Last profile update timestamp |
| `display_name` | `TEXT` | Nullable | None | Poet display name shown across site |
| `bio` | `TEXT` | Nullable | None | Poet biography (up to 50 words) |
| `photo_url` | `TEXT` | Nullable | None | Avatar URL from storage or OAuth |
| `email` | `TEXT` | Nullable | None | User email address |
| `role` | `TEXT` | Nullable | `'user'` | Role: `'user'`, `'semi-admin'`, or `'admin'` |
| `followers` | `UUID[]` | Not Null | `ARRAY[]::UUID[]` | Array of user IDs who follow this poet |
| `following` | `UUID[]` | Not Null | `ARRAY[]::UUID[]` | Array of user IDs this poet follows |

SQL Definition:
```sql
CREATE TABLE public.profiles (
  id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  updated_at TIMESTAMPTZ,
  display_name TEXT,
  bio TEXT,
  photo_url TEXT,
  email TEXT,
  role TEXT DEFAULT 'user',
  followers UUID[] DEFAULT ARRAY[]::UUID[],
  following UUID[] DEFAULT ARRAY[]::UUID[]
);
```

### 2. public.notes

Stores approved and published poems.

| Column | Data Type | Constraints | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | `GENERATED BY DEFAULT AS IDENTITY`, `PRIMARY KEY` | Sequence | Unique poem identifier |
| `created_at` | `TIMESTAMPTZ` | Nullable | `NOW()` | Publication timestamp |
| `user_id` | `UUID` | `REFERENCES public.profiles(id) ON DELETE SET NULL` | None | Author ID |
| `title` | `TEXT` | Not Null | None | Title of the poem |
| `content` | `TEXT` | Not Null | None | Full HTML formatted poem body |
| `preview` | `TEXT` | Nullable | None | Short excerpt for cards and search |
| `poet_name` | `TEXT` | Nullable | None | Display name of the poet at publish time |
| `tags` | `TEXT[]` | Nullable | None | Categorical tags (themes, moods) |
| `applause_count` | `INT` | Nullable | `0` | Cached counter of total applauses |

SQL Definition:
```sql
CREATE TABLE public.notes (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  user_id UUID REFERENCES public.profiles(id) ON DELETE SET NULL,
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  preview TEXT,
  poet_name TEXT,
  tags TEXT[],
  applause_count INT DEFAULT 0
);
```

### 3. public.poem_submissions

Queue for submitted poems pending administrator review.

| Column | Data Type | Constraints | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | `GENERATED BY DEFAULT AS IDENTITY`, `PRIMARY KEY` | Sequence | Unique submission identifier |
| `submitted_at` | `TIMESTAMPTZ` | Nullable | `NOW()` | Submission timestamp |
| `user_id` | `UUID` | `REFERENCES public.profiles(id) ON DELETE CASCADE` | None | Submitting user ID |
| `title` | `TEXT` | Not Null | None | Proposed poem title |
| `content` | `TEXT` | Not Null | None | Poem content |
| `description` | `TEXT` | Nullable | None | Note from poet to review team |
| `poet_name` | `TEXT` | Nullable | None | Submitter name |
| `tags` | `TEXT[]` | Nullable | None | Proposed tags |
| `status` | `TEXT` | Nullable | `'pending'` | Review status: `'pending'`, `'approved'`, `'rejected'` |

SQL Definition:
```sql
CREATE TABLE public.poem_submissions (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  submitted_at TIMESTAMPTZ DEFAULT NOW(),
  user_id UUID REFERENCES public.profiles(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  description TEXT,
  poet_name TEXT,
  tags TEXT[],
  status TEXT DEFAULT 'pending'

```

### 4. public.applauses

Tracks which users have applauded which poems.

| Column | Data Type | Constraints | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `note_id` | `BIGINT` | `REFERENCES public.notes(id) ON DELETE CASCADE` | None | Applauded poem ID |
| `user_id` | `UUID` | `REFERENCES public.profiles(id) ON DELETE CASCADE` | None | Applauding user ID |

Primary Key: `(note_id, user_id)` composite key prevents duplicate applauses.

SQL Definition:
```sql
CREATE TABLE public.applauses (
  note_id BIGINT REFERENCES public.notes(id) ON DELETE CASCADE,
  user_id UUID REFERENCES public.profiles(id) ON DELETE CASCADE,
  PRIMARY KEY (note_id, user_id)
);
```

### 5. public.bookmarks

Many-to-many relation storing user saved/bookmarked poems.

| Column | Data Type | Constraints | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `UUID` | `PRIMARY KEY` | `gen_random_uuid()` | Unique record identifier |
| `user_id` | `UUID` | `REFERENCES auth.users(id) ON DELETE CASCADE` | None | Saving user ID |
| `note_id` | `BIGINT` | `REFERENCES public.notes(id) ON DELETE CASCADE` | None | Bookmarked poem ID |
| `created_at` | `TIMESTAMPTZ` | Not Null | `NOW()` | Bookmark creation timestamp |

Constraints and Indexes:
- `UNIQUE(user_id, note_id)` prevents saving the same note more than once.
- `idx_bookmarks_user_id` on `public.bookmarks(user_id)` for quick retrieval of user bookmark feeds.
- `idx_bookmarks_note_id` on `public.bookmarks(note_id)` for quick check of bookmark status on notes.

SQL Definition:
```sql
CREATE TABLE public.bookmarks (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
    note_id BIGINT NOT NULL REFERENCES public.notes(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ DEFAULT now() NOT NULL,
    UNIQUE(user_id, note_id)
);

CREATE INDEX idx_bookmarks_user_id ON public.bookmarks(user_id);
CREATE INDEX idx_bookmarks_note_id ON public.bookmarks(note_id);
```

### 6. public.keep_alive

Internal maintenance table updated by pg_cron to satisfy Supabase free-tier project activity requirements.

| Column | Data Type | Constraints | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | `GENERATED ALWAYS AS IDENTITY`, `PRIMARY KEY` | Sequence | Singleton row identifier |
| `pinged_at` | `TIMESTAMPTZ` | Not Null | `NOW()` | Timestamp of last cron ping |

SQL Definition:
```sql
CREATE TABLE IF NOT EXISTS public.keep_alive (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  pinged_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

INSERT INTO public.keep_alive DEFAULT VALUES;
```

## Row Level Security (RLS) Policies

All tables have RLS enabled (`ALTER TABLE ... ENABLE ROW LEVEL SECURITY`).

### Policies on public.profiles

1. Public Read Access:
```sql
CREATE POLICY "Public profiles are viewable by everyone."
  ON public.profiles FOR SELECT
  USING ( true );
```

2. Owner Update Access:
```sql
CREATE POLICY "Users can update their own profile."
  ON public.profiles FOR UPDATE
  USING ( auth.uid() = id );
```

3. Admin Update Access:
Allows accounts with `'admin'` role to update any profile (such as assigning semi-admin roles).
```sql
CREATE POLICY "Admins can update user profiles."
  ON public.profiles FOR UPDATE
  USING ( (SELECT role FROM public.profiles WHERE id = auth.uid()) = 'admin' )
  WITH CHECK ( (SELECT role FROM public.profiles WHERE id = auth.uid()) = 'admin' );
```

### Policies on public.notes

1. Public Read Access:
```sql
CREATE POLICY "Poems are viewable by everyone."
  ON public.notes FOR SELECT
  USING ( true );
```

2. Authenticated Creation Access:
```sql
CREATE POLICY "Users can create poems (via submissions)."
  ON public.notes FOR INSERT
  WITH CHECK ( auth.role() = 'authenticated' );
```

3. Owner or Admin Management Access:
Allows author or admin/semi-admin to modify or delete poems.
```sql
CREATE POLICY "Owners or admins can update/delete poems."
  ON public.notes FOR ALL
  USING (
    auth.uid() = user_id
    OR (SELECT role FROM public.profiles WHERE id = auth.uid()) IN ('admin', 'semi-admin')
  );
```

### Policies on public.poem_submissions

1. Submitter Creation Access:
```sql
CREATE POLICY "Users can create submissions."
  ON public.poem_submissions FOR INSERT
  WITH CHECK ( auth.uid() = user_id );
```

2. Admin Management Access:
Allows admins and semi-admins to view, update, approve, or reject submissions.
```sql
CREATE POLICY "Admins can manage submissions."
  ON public.poem_submissions FOR ALL
  USING ( (SELECT role FROM public.profiles WHERE id = auth.uid()) IN ('admin', 'semi-admin') );
```

### Policies on public.applauses

1. User Self Management:
Users can only insert or remove their own applause records.
```sql
CREATE POLICY "Users can manage their own applauses."
  ON public.applauses FOR ALL
  USING ( auth.uid() = user_id );
```

### Policies on public.bookmarks

1. User Read Self Bookmarks:
```sql
CREATE POLICY "Users can view their own bookmarks"
    ON public.bookmarks FOR SELECT
    USING (auth.uid() = user_id);
```

2. User Insert Self Bookmarks:
```sql
CREATE POLICY "Users can create their own bookmarks"
    ON public.bookmarks FOR INSERT
    WITH CHECK (auth.uid() = user_id);
```

3. User Delete Self Bookmarks:
```sql
CREATE POLICY "Users can delete their own bookmarks"
    ON public.bookmarks FOR DELETE
    USING (auth.uid() = user_id);
```

4. Note Owner View Bookmarks:
Poets can see which users bookmarked their poems.
```sql
CREATE POLICY "Note owners can view bookmarks on their notes"
    ON public.bookmarks FOR SELECT
    USING (
        EXISTS (
            SELECT 1 FROM public.notes
            WHERE notes.id = note_id
            AND notes.user_id = auth.uid()
        )
    );
```

## Stored Functions and Triggers

### 1. New User Creation Trigger

Automatically provisions a record in `public.profiles` upon successful sign-up in Supabase Auth.

```sql
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO public.profiles (id, email, photo_url)
  VALUES (new.id, new.email, new.raw_user_meta_data->>'avatar_url');
  RETURN new;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE PROCEDURE public.handle_new_user();
```

### 2. Applause Toggle RPC

Safely manages applause insertions/deletions and updates the cached counter in `public.notes` atomically.

```sql
CREATE OR REPLACE FUNCTION toggle_applause(p_note_id BIGINT, p_is_applauded BOOLEAN)
RETURNS void AS $$
BEGIN
  IF p_is_applauded THEN
    DELETE FROM public.applauses WHERE user_id = auth.uid() AND note_id = p_note_id;
    UPDATE public.notes SET applause_count = applause_count - 1 WHERE id = p_note_id;
  ELSE
    INSERT INTO public.applauses (user_id, note_id) VALUES (auth.uid(), p_note_id);
    UPDATE public.notes SET applause_count = applause_count + 1 WHERE id = p_note_id;
  END IF;
END;
$$ LANGUAGE plpgsql;
```

### 3. Follow Management RPC

Updates the `following` and `followers` arrays on both profile records atomically.

```sql
CREATE OR REPLACE FUNCTION handle_follow(p_target_user_id UUID, p_is_following BOOLEAN)
RETURNS void AS $$
BEGIN
  IF p_is_following THEN
    UPDATE public.profiles SET following = array_remove(following, p_target_user_id) WHERE id = auth.uid();
    UPDATE public.profiles SET followers = array_remove(followers, auth.uid()) WHERE id = p_target_user_id;
  ELSE
    UPDATE public.profiles SET following = array_append(following, p_target_user_id) WHERE id = auth.uid();
    UPDATE public.profiles SET followers = array_append(followers, auth.uid()) WHERE id = p_target_user_id;
  END IF;
END;
$$ LANGUAGE plpgsql;
```

## Storage Configuration and Policies

Avatars and profile photos are stored in the Supabase Storage bucket named `pfp`.

### Bucket Creation

```sql
INSERT INTO storage.buckets (id, name, public)
VALUES ('pfp', 'pfp', true)
ON CONFLICT (id) DO NOTHING;
```

### Storage Security Policies

```sql
DROP POLICY IF EXISTS "Public read access for pfp bucket" ON storage.objects;
DROP POLICY IF EXISTS "Allow authenticated users to upload to their own folder" ON storage.objects;
DROP POLICY IF EXISTS "Allow authenticated users to update their own pfp" ON storage.objects;

-- 1. Public read access
CREATE POLICY "Public read access for pfp bucket"
ON storage.objects FOR SELECT
TO public
USING ( bucket_id = 'pfp' );

-- 2. Authenticated user upload to user-scoped folder
CREATE POLICY "Allow authenticated users to upload to their own folder"
ON storage.objects FOR INSERT
TO authenticated
WITH CHECK ( bucket_id = 'pfp' AND auth.uid()::text = (storage.foldername(name))[1] );

-- 3. Authenticated user update inside user-scoped folder
CREATE POLICY "Allow authenticated users to update their own pfp"
ON storage.objects FOR UPDATE
TO authenticated
USING ( bucket_id = 'pfp' AND auth.uid()::text = (storage.foldername(name))[1] );
```

## Supabase Inactivity Keep-Alive (pg_cron)

Supabase free-tier projects automatically pause after 7 days of database inactivity. The application uses the PostgreSQL extension `pg_cron` to perform a lightweight update every 3 days.

### Schedule Setup

```sql
-- 1. Enable extension
CREATE EXTENSION IF NOT EXISTS pg_cron;

-- 2. Create ping table
CREATE TABLE IF NOT EXISTS public.keep_alive (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  pinged_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

INSERT INTO public.keep_alive DEFAULT VALUES;

-- 3. Schedule job to execute every 3 days at 12:00 UTC
SELECT cron.schedule(
  'keep-alive-ping',
  '0 12 */3 * *',
  $$
    UPDATE public.keep_alive SET pinged_at = NOW() WHERE id = 1;
  $$
);
```

### Inspection and Diagnostic Queries

Check existing jobs:
```sql
SELECT * FROM cron.job;
```

Check the 5 most recent executions:
```sql
SELECT * FROM cron.job_run_details
ORDER BY start_time DESC
LIMIT 5;
```

Unschedule or delete job if needed:
```sql
SELECT cron.unschedule('keep-alive-ping');
```
